# vSpec 0.15.2 冷启动优化试验

此版本只调整动态臂的静态算子预编译形状选择。完整解码图捕获列表、运行时可达形状和推测预算控制策略不变。动态臂默认预编译热形状 `70`；如需复用 0.15.1 的五形状行为，可显式设置 `HUST_VSPEC_HOT_STATIC_SHAPES=14,42,70,98,126`。公开配对入口的原生臂保持五形状配置；动态臂使用 `configs/v0.15.2-dynamic-hot-static.fragment.json` 中的单形状配置。这是两臂编译策略上的显式差异，不能把观察到的运行期吞吐差异仅归因于动态预算选择。

在私有 `dynamic-env.json` 中加入 `"HUST_VSPEC_HOT_STATIC_SHAPES": "70"`，`common-env.json` 仍按 [配对入口](../examples/qwen35_three_datasets/README.md)保留公共五形状设置。启动记录应保存各臂实际环境、完整图捕获数量、编译缓存是否复用，以及服务就绪时间。安装插件不会提前生成与模型、设备和服务配置有关的图。

本机验证使用两张 910B2、Qwen3.5-35B-A3B、自动 KV、完整 64 张解码图、独立私有编译目录，未复用旧编译缓存，亦未额外运行数据集预热题。0.15.1 原配置就绪耗时 2761.12 秒，其中图捕获约 2156 秒；0.15.2 单热形状试验就绪耗时 1042.50 秒，其中图捕获约 513 秒。随后从 0.15.2 候选 wheel 安装的独立环境复测，就绪耗时 1034.47 秒，其中图捕获约 516 秒。两轮 0.15.2 冷启动均低于 20 分钟。

以上是本机同类硬件与软件栈的**首次编译目录**观测值，不是跨机器启动时长保证；复制已有 Triton/静态算子缓存后的约数分钟启动属于另一种热缓存口径。评测脚本不再写死设备号，而是使用目标机已分配的两张可见 NPU。私有运行根目录须足够短：在本机 CANN 版本上，长路径会被编码进单个静态编译文件名并触发 `File name too long`；入口会在启动前拒绝过长路径。

三轮 FrontierScience 160 题求解均为 160/160 请求成功、无传输失败。0.15.1 原配置、0.15.2 首次试验、0.15.2 wheel 复测的输出吞吐依次为 1244.50、1211.93、1230.39 token/s；后两轮相对原配置分别低约 2.6% 和 1.1%。自然生成的输出 token 数不同，这些单轮观察不能证明稳定的吞吐差异，也不能用来推断任务质量。服务启动时间不计入求解阶段吞吐。

wheel 复测中的运行元数据在两个 TP rank 上一致，记录到预算 2、4、6、8 的实际帧以及 30 次档位切换。这说明单热形状仅缩小预编译集合，没有把在线预算固定在某一档；它不是解码图回放次数的证明。

## 复现入口与参数

安装前置条件、后端和算子的构建及校验沿用 [0.15.1 复现准备](v0.15.1-reproduction.md)，但安装包应选择 **0.15.2 wheel**。评测使用仓库中的 [配对脚本](../examples/qwen35_three_datasets/paired.py)和[选题脚本](../examples/qwen35_three_datasets/select_cases.py)。本轮 FrontierScience 的完整公共服务参数保存在 [`v0.15.2-frontierscience-common.json`](../configs/v0.15.2-frontierscience-common.json)，公共非路径环境设置保存在 [`v0.15.2-common-env.example.json`](../configs/v0.15.2-common-env.example.json)，动态臂静态形状覆盖保存在 [`v0.15.2-dynamic-hot-static.fragment.json`](../configs/v0.15.2-dynamic-hot-static.fragment.json)。公共配置使用自动 KV、并发 16、完整 79 项 capture-size 输入列表；启动日志中观察到的实际解码图数为 64，两者不是同一指标。

操作者须按[三数据集入口说明](../examples/qwen35_three_datasets/README.md)自行准备模型、已许可的数据集、冻结的 FrontierScience 双轨 160 题计划、客户端、私有算子 proof 路径和两臂隔离 Python 环境。`dynamic-env.json` 应以[非路径开关清单](v0.15.1-local-dynamic-env.json)为起点，在私有目录补齐安装器生成的 proof 路径，并加入 `HUST_VSPEC_HOT_STATIC_SHAPES=70`；不要将私有文件、模型、题目或凭据提交仓库。本轮请求设置为温度 0、请求 seed 17、每题最多输出 16384 token、并发 16、1800 秒超时，关闭 thinking；这些任务级参数由冻结的客户端计划控制，不由公共服务 JSON 控制。

以下展示同一冻结计划上的动态臂命令骨架；路径须替换为本机实际路径。准备命令还需要原生环境以固定配对设置，但只执行 `dynamic` 臂即可复核本轮冷启动和吞吐。首次执行请使用新的私有运行目录和编译缓存；不传 `--warmup-selection`，即不额外发送数据集预热题。`run` 会启动服务、等待就绪、清理运行缓存、计时求解并停止服务。若需比较原生 MTP4/6/8，再以相同计划和公共配置分别新建 setup，执行对应 `native` 臂；不要把不同题单或缓存口径混在一轮结果里。

```bash
VSPEC_REPO=/absolute/path/to/vllm-hust-vSpec
PRIVATE_ROOT=/absolute/path/to/new-private-run
CLIENT_PYTHON=/absolute/path/to/client-venv/bin/python

"$CLIENT_PYTHON" "$VSPEC_REPO/examples/qwen35_three_datasets/paired.py" prepare \
  --private-root "$PRIVATE_ROOT" --model-dir <MODEL_DIR> \
  --common-config "$VSPEC_REPO/configs/v0.15.2-frontierscience-common.json" \
  --common-env "$VSPEC_REPO/configs/v0.15.2-common-env.example.json" \
  --dynamic-env <PRIVATE_DYNAMIC_ENV_JSON> \
  --native-python <NATIVE_VENV_PYTHON> --dynamic-python <DYNAMIC_VENV_PYTHON> \
  --client-python "$CLIENT_PYTHON" \
  --native-backend-package <NATIVE_SITE_PACKAGES> \
  --dynamic-backend-package <DYNAMIC_SITE_PACKAGES> \
  --native-evaluation-dir <NATIVE_EVALUATION_DIR> \
  --dynamic-evaluation-dir <DYNAMIC_EVALUATION_DIR> \
  --served-model paired-solver --port 18080 --native-capacity 4

"$CLIENT_PYTHON" "$VSPEC_REPO/examples/qwen35_three_datasets/paired.py" run \
  --setup "$PRIVATE_ROOT/setup.json" --arm dynamic \
  --dataset frontierscience --plan <PRIVATE_FRONTIER_PLAN> \
  --selection <PRIVATE_FRONTIER_FULL_SELECTION_JSON> \
  --tag cold-r1 --execute
```

脚本、参数与本页聚合观测值可用于重新开展同口径实验，**不能单凭仓库文件重建历史逐题结果或保证相同吞吐**。本轮未做任务质量判分，冷启动优化的验收范围只覆盖服务就绪、请求成功、动态切换存在及上述单轮吞吐观察。0.15.1 已发布包和原有实验记录不因本版本而改变。
