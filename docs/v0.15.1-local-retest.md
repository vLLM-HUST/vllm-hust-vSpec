# vSpec 0.15.1 本地复测参数与聚合结果

本文记录本地 Ascend 环境中的观测值，供检查实验口径和重新开展测试使用。它不是官方数据集榜单，也不是“安装后必然获得相同数值”的保证。四方案对照与其后的安装包诊断是两组独立实验，不能拼接为同一轮验收。

## 环境与共同服务配置

| 项目 | 本地配置 |
|---|---|
| 模型 | Qwen3.5-35B-A3B，原模型 MTP 头，BF16；两张 Ascend 910B2，TP=2、EP 开启，顺序独占运行 |
| 软件 | Python 3.11；vLLM-HUST `762f85b311fbab0bcf8921dd216f5093cd58b9`；vLLM-Ascend-HUST 基础修订 `4e57439e58ed3d78e675f9fd7b4614fb183c5394` 加安装包后端补丁；vSpec 0.15.1；CANN 9.1；PyTorch 2.13.0；torch-npu 2.13.0rc1；triton-ascend 3.6.0+git148a35c0 |
| 并发与内存 | `max_num_seqs=16`，`max_num_batched_tokens=8192`，`gpu_memory_utilization=0.85`，`block_size=128`，`kv_cache_memory_bytes=null`（自动分配） |
| 执行路径 | 前缀缓存、异步调度、分块预填充开启；`mamba_cache_mode=align`；编译 `mode=3`、`FULL_DECODE_ONLY`、`enable_npugraph_ex=true`、`enable_static_kernel=true` |
| 随机性与兼容 | 服务 `seed=0`、请求 `seed=17`；两臂均启用相同的 Qwen3.5 MTP KV/Mamba 兼容桥；请求温度 0，关闭 thinking |

MMLU-Pro 与 FrontierScience 的 `max_model_len=32768`、`language_model_only=true`；HLE-Verified Gold 的 `max_model_len=65536`、`language_model_only=false`、每请求最多 1 张图像和 0 个视频。公共编译环境还设置 `HUST_VSPEC_CAPTURE_SAFE_STATIC=1`、`HUST_VSPEC_HOT_STATIC_SHAPES=14,42,70,98,126`、`HCCL_BUFFSIZE=1024`、`HCCL_OP_EXPANSION_MODE=AIV`、`PYTORCH_NPU_ALLOC_CONF=expandable_segments:True`、`OMP_NUM_THREADS=1`、`PYTHONHASHSEED=0`、`VLLM_DISABLE_SHARED_EXPERTS_STREAM=1`、`VLLM_USE_AOT_COMPILE=0`、`VLLM_USE_BREAKABLE_CUDAGRAPH=0`、`VLLM_WORKER_MULTIPROC_METHOD=spawn`。系统驱动、CANN 路径和可见设备号须按目标主机设置，不应照搬私人机器的绝对路径。

原生臂分别设置 `num_speculative_tokens=4/6/8`。vSpec 臂容量为 8，在线候选为 2/4/6/8，从 8 起步；`HUST_VSPEC_ADAPTIVE_POLICY=online`、`HUST_VSPEC_ADAPTIVE_CONTROL_INTERVAL=1`、`HUST_VSPEC_ADAPTIVE_ONLINE_WINDOW=16`、`HUST_VSPEC_ADAPTIVE_HYSTERESIS=0.03`、`HUST_VSPEC_ADAPTIVE_MAX_GAMMA_STEP=2`、`HUST_VSPEC_ADAPTIVE_FULL_GRAPH=1`。动态臂还启用安装包中的 Qwen3.5 专用后端和已验证算子；原生臂不加载动态 vSpec worker。因此吞吐差异是整个实现的差异，不能仅归因于档位选择器。完整构建、安装和算子校验步骤见[复现准备文档](v0.15.1-reproduction.md)。

[动态臂非路径环境变量清单](v0.15.1-local-dynamic-env.json)保存了本地诊断轮次的实际开关。它不含私有 proof 路径，不能直接作为评测入口的完整 `dynamic-env.json`；安装器生成本机算子与证明目录后，须按复现准备文档在私有文件中补齐路径。服务共同配置还使用 `speculative_config={"method":"mtp","enforce_eager":false,"use_local_argmax_reduction":true}`、`additional_config.enable_cpu_binding=true`、`generation_config="vllm"`、`structured_outputs_config={"backend":"xgrammar","disable_any_whitespace":true}`。共同环境中的系统 `LD_LIBRARY_PATH` 和设备可见性由本机 CANN 与设备分配决定。

本地使用的完整 decode 图捕获 batch-size 列表为：`1–16, 18, 20, 21, 22, 24, 25, 26, 27, 28, 30, 33, 35, 36, 39, 40, 42, 44, 45, 48, 49, 50, 52, 54, 55, 56, 60, 63, 65, 66, 70, 72, 75, 77, 78, 80, 81, 84, 88, 90, 91, 98, 99, 104, 105, 108, 110, 112, 117, 121, 126, 130, 132, 135, 143, 144, 154, 156, 165, 169, 176, 182, 195, 208`。它显著增加首次图捕获工作量；缩小列表前需重新检查图覆盖范围及吞吐。

## 负载、评分与计时

| 数据集 | 冻结负载 | 请求与质量口径 |
|---|---|---|
| MMLU-Pro | 跨学科 200 题 | 5-shot CoT；每题最多 2048 输出 token；并发 16；A–J 答案抽取，截断题照常计分 |
| FrontierScience | Olympiad 100 题 + Research 60 题 | 每题最多 16384 输出 token；并发 16；超时 1800 秒；吞吐合计两轨，正确率仅列 Olympiad；独立本地 Qwen 替代判分服务，判分上限 8192 token |
| HLE-Verified Gold | 200 题，其中 172 文本、28 图像 | 每题最多 16384 输出 token；并发 16；超时 1800 秒；独立本地 Qwen 替代严格 JSON 判分服务，判分上限 8192 token |

没有额外发送数据集预热题，但服务启动仍包含模型探测、编译预热及图捕获；正式计时前重置前缀、编码器及多模态缓存。输出吞吐为**求解阶段实际 completion token 总数 ÷ 客户端求解墙钟时间**，不包含服务启动、缓存重置和判分。自然生成的 token 数不相同，因此 token/s 比值不能直接当作固定工作量的端到端时间加速比。各方案仅运行一遍，未给出置信区间。

本地冻结计划的 `contract.json` SHA-256：MMLU-Pro `dbbf4204d8c40ffe4d98624d7ce83bb2cc4e489be651caff8434d525118217dd`；FrontierScience `4ec0935be6dc3f2fa016b9cabcfd55fd9afa1d5bbd66486aea3feb4bc7dd1bc6`；HLE-Verified `d055e652bfa6d4277ea76547e19b7fffed8ccb30fe6bd64e230096759d450c7a`。题目 ID 列表和提示词不随仓库发布。公开评测入口的 `select_cases.py` 提供新的可复现抽样方法，但**与这组历史冻结题单的抽样算法不同**；只凭这些哈希不能重新生成逐题相同的计划。可用相同参数在自己冻结的计划上独立复测，不能将数值差异仅解释为代码变化。

## 后续安装包诊断轮次（不与上表混算）

后续在重新安装插件后的独立服务轮次中，MMLU-Pro 200 题的 vSpec 为 643.90 token/s、162/200；另一次原生 MTP4 为 626.64 token/s、159/200。两次求解吞吐比约 1.03，未达到 1.10；它们不是严格同时配对的一轮。FrontierScience 后续冷服务轮次中，vSpec 为 1222.06 token/s、Olympiad 63/100，原生 MTP6 为 1035.13 token/s、66/100；同样是跨轮诊断，不用于替换上表。当前不能把四方案表格当作“干净安装后稳定复现”的证明。

冷启动比原生 MTP 慢仍是已知问题。若为了复测复用编译或图缓存，应单独记录缓存目录和命中情况；不得与真正首次启动混报。更多限制及公开执行命令见[三数据集入口](../examples/qwen35_three_datasets/README.md)。
