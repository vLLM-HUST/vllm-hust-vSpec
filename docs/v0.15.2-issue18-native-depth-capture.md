# Issue #18 冻结 56 题：原生 MTP4/6/8 与图捕获上限

2026-11-11 在当前双 910B2 主机上，用老师公开的[冻结原生复现包](https://github.com/vLLM-HUST/vllm-hust-benchmark/tree/d67aea6eb3eb0dee271a01b4d66acce8b65bd034/reports/reproductions/native-mtp4-gamma4-20261027)补测原生 MTP 深度。先保持原始 48 个图捕获尺寸（最大 112）运行 MTP4 一轮、MTP6 三轮和 MTP8 一轮；MTP8 虽成功完成，但后端警告解码可能需要 144，吞吐异常低。随后仅在原列表末尾增加 `117, 126, 135, 144`，以 52 个尺寸、最大 144 重测 MTP8 三轮。中途停止的一轮 MTP8/112 不计成绩。

| 原生模式 | 图尺寸数／上限 | 正式输出 token/s（各轮） | 中位数 | 用途 |
| --- | ---: | --- | ---: | --- |
| MTP4 | 48／112 | 829.53 | — | 额外单轮，非三轮统计 |
| MTP6 | 48／112 | 841.55、846.83、850.80 | 846.83 | 原始列表三轮 |
| MTP8 | 48／112 | 233.61 | — | 图覆盖不足诊断轮 |
| MTP8 | 52／144 | 791.13、781.00、783.17 | 783.17 | 扩容后三轮 |

所有纳入表格的轮次均完成同序的 56/56 题，输入合计 76,907 token，退出码 0、无无法解析的答案，日志未见抢占。逐轮实际输出 token 数、正式耗时、正确数、捕获尺寸和退出状态见[机器可读结果](../examples/issue18_frozen56/result-20261111-native-depth-capture.json)。正确数只用于小样本运行诊断，不代表 MMLU-Pro 全量正确率。

正式题为一次离线 `LLM.generate` 提交、最多 4000 token／题、自然停止；正式吞吐按**实际输出 token 总数／正式生成墙钟时间**计算，不含每轮重新启动引擎及 14 题 × 16 token pilot。使用 Qwen chat template、温度 0、`top_p=1`、Qwen3.5-35B-A3B、BF16、TP=2、EP、最大并发 16、`max_model_len=16384`、`max_num_batched_tokens=8192`、APC、异步调度、分块预填充、自动 KV (`gpu_memory_utilization=0.9`) 和 `FULL_AND_PIECEWISE`。原生臂用 `VLLM_PLUGINS=ascend`、`use_local_argmax_reduction=false`；除 MTP 深度与明确标出的图尺寸外，各轮参数不变。两份冻结输入 SHA-256 分别为 `9ee8849d84172ec7fd04ceeea71c4123a2eb53111d1334b85a5f987c86064462`（56 题）和 `0e1eeeb81f7b8a784a29083a5ae79c47931a5b80bc43a688a281ee7a46843317`（pilot）。

原始图上限 112 正好覆盖并发 16 的 MTP6 解码 `16 × (6+1) = 112`，但小于 MTP8 的 `16 × (8+1) = 144`。MTP8/112 日志出现后端的图上限警告，扩到 144 后警告消失，首轮吞吐从 233.61 升至 791.13 token/s。这个对照强烈支持**图覆盖不足是低速主因**；没有逐步执行路径追踪，不能断言所有差异都由 eager 回退造成。扩容后的 MTP8 中位数仍低于 MTP6，不能把“候选 token 更多”等同于“吞吐更高”。MTP4 只有这次一轮，不能用它估计稳定中位数；各深度自然停止的输出 token 总数也不同。

## 复测入口

使用本仓库的[配置生成脚本](../examples/issue18_frozen56/prepare_native_depth.py)从上述老师的冻结包生成**新目录**。它校验原始 48 项列表，只改原生 `num_speculative_tokens`，并按选择保留 112 或在末尾增加 4 个尺寸至 144；不写死设备编号。下面的 `CAPSULE` 指向公开复现包目录，`VENV` 指向本机已安装匹配 vLLM/Ascend/CANN 的虚拟环境，`CARDS` 由运行者填入本机实际可用的物理 NPU 编号。每轮换新的 `RUN` 和 `LABEL`，不要并发占同一对 NPU。

```bash
REPO=/path/to/vllm-hust-vSpec
CAPSULE=/path/to/native-mtp4-gamma4-20261027
VENV=/path/to/venv
SITE_PACKAGES="$VENV/lib/python3.11/site-packages"
CARDS=0,1  # 按本机实际分配修改；不是插件内置绑定
RUN=/short/path/native-mtp8-r1
LABEL=native-mtp8-r1

"$VENV/bin/python" "$REPO/examples/issue18_frozen56/prepare_native_depth.py" \
  --capsule "$CAPSULE" --output "$RUN" --depth 8 --capture-max 144
ln -s "$VENV" "$RUN/venv"

export QWEN35_MTP_COMPAT=1
export QWEN35_COMPAT_STARTUP_FILE="$SITE_PACKAGES/vllm_hust_vspec/_vendor/qwen35_mtp_compat/sitecustomize.py"
export PYTHONPATH="$SITE_PACKAGES/vllm_hust_vspec/_vendor/qwen35_mtp_compat${PYTHONPATH:+:$PYTHONPATH}"
export HCCL_BUFFSIZE=1024 HCCL_OP_EXPANSION_MODE=AIV
export VLLM_PLUGINS=ascend VLLM_WORKER_MULTIPROC_METHOD=spawn VLLM_USE_AOT_COMPILE=0
export VLLM_NO_USAGE_STATS=1 PYTHONDONTWRITEBYTECODE=1 PYTHONHASHSEED=0
export PYTORCH_NPU_ALLOC_CONF=expandable_segments:True TOKENIZERS_PARALLELISM=false
export LUMI_TIMEOUT_SECONDS=1800
(cd "$RUN" && ./venv/bin/python launch_gamma4.py "$CARDS" "$LABEL" screen_gamma4.py q35-mtp4 perf56)
```

对 MTP4 或 MTP6，将 `--depth` 改为 `4` 或 `6`、`--capture-max` 改为 `112`；若专门诊断 MTP8 原始上限，则用 `--depth 8 --capture-max 112`，但不要与扩容后三轮混算。老师启动脚本会在所选机器上映射和检查卡号；生成脚本与插件包本身均不绑定物理卡。模型目录需对应冻结配置中的本机路径，题单和 pilot 来自公开复现包。当前软件栈为 `vllm 0.17.2rc1.dev5871+g762f85b31.empty`、`vllm_ascend 0.25.1rc2.dev0+hust.20260903.4.g4e57439e5.d20261111`，并为两臂共用已安装插件的 Qwen3.5 MTP **启动兼容桥接**；这不是老师 2026-10-27 历史二进制环境的逐字节重放，跨机器吞吐不能保证完全相同。
