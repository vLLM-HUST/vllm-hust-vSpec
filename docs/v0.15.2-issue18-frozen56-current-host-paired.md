2026-11-11，按老师公开的[原生 MTP4 冻结复现包](https://github.com/vLLM-HUST/vllm-hust-benchmark/tree/d67aea6eb3eb0dee271a01b4d66acce8b65bd034/reports/reproductions/native-mtp4-gamma4-20261027)所定义的**输入与计时边界**，在同一台双 910B2 主机上连续执行三组 `native → vSpec`。每轮重新启动离线 `LLM`；使用同一冻结 56 题和不重叠的 14 道 pilot 题，Qwen chat template，pilot 每题最多输出 16 token，正式题每题最多输出 4000 token、自然停止。正式输出吞吐为 `sum(len(rows[*].output_tokens)) / elapsed`，`elapsed` 仅覆盖正式的单次 `LLM.generate`，不含启动与 pilot。**固定输出 1024 token 是另一种负载，不参与本表。**

## 环境与参数边界

- 安装包：`vllm-hust-vspec 0.15.2.post1`；基础环境为 `vllm 0.17.2rc1.dev5871+g762f85b31.empty` 和 `vllm_ascend 0.25.1rc2.dev0+hust.20260903.4.g4e57439e5.d20261111`，两臂共用同一 Python 环境与两张 910B2 NPU，不并行占用设备。
- 模型与共同引擎参数：Qwen3.5-35B-A3B、BF16、TP=2、EP 开启、`max_model_len=16384`、`max_num_seqs=16`、`max_num_batched_tokens=8192`、APC、异步调度、分块预填充、自动 KV（`gpu_memory_utilization=0.9`）、`FULL_AND_PIECEWISE`。两个引擎配置除投机与插件必需的设置外相同。
- 原生：`num_speculative_tokens=4`；vSpec：最大深度 8、动态选择 2/4/6/8，并启用已安装插件的 worker、本地 argmax reduction 与 Mamba cache alignment。这个倍率衡量**完整插件/后端/算子运行栈**，不能单独归因于自适应策略。
- 冻结输入 SHA-256：`perf56.jsonl` 为 `9ee8849d84172ec7fd04ceeea71c4123a2eb53111d1334b85a5f987c86064462`，`pilot.jsonl` 为 `0e1eeeb81f7b8a784a29083a5ae79c47931a5b80bc43a688a281ee7a46843317`；公开复现包检出提交为 `d67aea6eb3eb0dee271a01b4d66acce8b65bd034`。

## 与老师历史环境的差异

这次是**当前环境的匹配配对复测，不是 2026-10-27 旧软件栈的逐字节重放**。老师原始启动包的底层提交与当前已安装的 vLLM/Ascend 版本不同；原脚本在当前栈上直接运行会在正式题前因 Qwen3.5 MTP attention layer index 兼容问题失败。因此，两臂都加载已安装包中的同一 Qwen3.5 启动兼容桥接。老师原生配置列出的图捕获尺寸为 48 个；当前插件动态最大深度 8 会触发其范围外的形状，两臂遂共同改用仓库[自动 KV 配置](../configs/v0.15.2-issue18-frozen56-auto-kv.json)中的 79 个捕获尺寸，图模式仍为 `FULL_AND_PIECEWISE`。当前原生在老师原有 48 个尺寸下另有一次 795.22 token/s 的成功单轮，仅作参照，**不与 79 尺寸的 vSpec 相除**。

复测时从公开复现包运行其 `launch_gamma4.py` 和冻结的题单、pilot、计时/评分逻辑；本地适配仅为双方共同注入兼容桥接和 79 尺寸覆盖，以及在 vSpec 臂启用当前安装包所需的 worker、argmax/Mamba 设置。原生和 vSpec 的六份引擎配置及完整结果保存在本地私有评测目录；仓库只提交脱敏聚合结果，不提交模型生成正文、模型文件、缓存或安装凭据。上述差异意味着后续若要宣称“老师历史环境的原样复现”，仍须用其冻结的底层提交、算子和原始图配置另行测量。
